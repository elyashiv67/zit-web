Going live on a private server with Docker

Every step from an empty Ubuntu server to the app running over HTTPS, with commands, a check after each step, and the full config files in the appendix. It covers the open must-do items (M1–M9) from docs/security-report.html; every code-level item there is already fixed and tested.

Read first

The config files below have not been run yet. Docker isn't installed on the development PC, so they couldn't be tested. Every value in them was checked against the code (ports, paths, env names, the /zit-web/ base, the /api prefix, sharp's Linux binary in the lock file), and each step ends with a check that catches mistakes right away. Expect one or two small fixes on the first real run.

Compared with your docker-try branch (an earlier attempt before the frontend existed), this setup:

  • adds nginx, which serves the React app, handles HTTPS, and passes /api to Node;
  • no longer publishes port 4586 (the API is reachable only through nginx);
  • gives Mongo a password and an app user that can only use the Zit database;
  • runs Node as a non-root user on Node 24, the same version as your PC;
  • stores pin photos on a volume, so they survive rebuilds;
  • adds health checks;
  • no longer needs environment/ on the server: nothing imports it anymore.

Placeholders used below: zit.example.org = your domain · SERVER_IP = the server's address · deploy = the Linux user you work as · /srv/zit = where the code lives on the server. Replace them everywhere.

This file is in .claude/reports/, which git tracks, and the repo is public. It has no secrets, real names or addresses, and it should stay that way: never paste real passwords, connection strings or your real domain into it.

1

Prepare and secure the server server

A user for you, SSH by key only, a firewall, and automatic security updates.

# as root (or the first user the provider gave you)
adduser deploy
usermod -aG sudo deploy

# on YOUR PC: copy your SSH key to the server, then log in as deploy
ssh-copy-id deploy@SERVER_IP
ssh deploy@SERVER_IP

# key-only SSH, no root login
sudo tee /etc/ssh/sshd_config.d/99-zit.conf >/dev/null <<'EOF'
PasswordAuthentication no
PermitRootLogin no
EOF
sudo systemctl restart ssh

# updates, time zone, firewall
sudo apt update && sudo apt full-upgrade -y
sudo apt install -y unattended-upgrades ufw
sudo dpkg-reconfigure -plow unattended-upgrades     # answer Yes
sudo timedatectl set-timezone Asia/Jerusalem
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable

Check

  • Keep your current SSH window open and log in from a second window: ssh deploy@SERVER_IP should work with your key, and ssh root@SERVER_IP should be refused.
  • sudo ufw status shows only OpenSSH, 80 and 443.
2

Install Docker server

From Docker's own apt repository (Ubuntu's docker.io package lags behind), with log rotation turned on for every container.

sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" \
  | sudo tee /etc/apt/sources.list.d/docker.list >/dev/null
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

# rotate container logs (10 MB × 5 files each), so logs can't fill the disk
sudo tee /etc/docker/daemon.json >/dev/null <<'EOF'
{ "log-driver": "json-file", "log-opts": { "max-size": "10m", "max-file": "5" } }
EOF
sudo systemctl restart docker

# run docker without sudo (log out and back in afterwards)
sudo usermod -aG docker deploy

Check

  • docker run --rm hello-world prints "Hello from Docker!".
  • docker compose version prints v2.x.

Good to know

  • Ports that Docker publishes skip ufw. Only web publishes ports (80/443). Never add a ports: line to api or mongo expecting the firewall to block it; it won't.
  • Being in the docker group is equivalent to root. Keep it to the deploy user.

4

Get the code onto the server server

The server pulls from GitHub. It never needs your .env, environment/ or node_modules.

sudo mkdir -p /srv/zit && sudo chown deploy: /srv/zit
git clone https://github.com/elyashiv67/zit-web.git /srv/zit
cd /srv/zit
git checkout v1.0.0          # the tag from step 3

If the repo is private

Create a read-only deploy key on the server and add it under GitHub → repo → Settings → Deploy keys (leave "write access" off). Then clone with the SSH URL:

ssh-keygen -t ed25519 -f ~/.ssh/zit_deploy -N ""
cat ~/.ssh/zit_deploy.pub          # paste into GitHub → Deploy keys
printf 'Host github.com\n  IdentityFile ~/.ssh/zit_deploy\n' >> ~/.ssh/config
git clone git@github.com:elyashiv67/zit-web.git /srv/zit

Check

  • ls /srv/zit shows server/, react/, deploy/, docker-compose.yml.
5

Create the secrets server

Three files, readable only by you. Use openssl rand -hex for database passwords: hex characters never need escaping in a connection string.

cd /srv/zit
cp .env.example .env                       # DOMAIN=zit.example.org
cp deploy/api.env.example deploy/api.env
cp deploy/mongo.env.example deploy/mongo.env
chmod 600 .env deploy/api.env deploy/mongo.env

openssl rand -base64 48     # → SESSION_SECRET in deploy/api.env (new; never reuse the dev one)
openssl rand -hex 24        # → MONGO_INITDB_ROOT_PASSWORD in deploy/mongo.env
openssl rand -hex 24        # → ZIT_APP_PASSWORD in deploy/mongo.env, AND inside DB= in deploy/api.env
nano deploy/api.env  &&  nano deploy/mongo.env  &&  nano .env

DVR_SECRET: copy it, don't create a new one

The DVR passwords already in the database are encrypted with the DVR_SECRET from your current server/.env. Copy that exact value into deploy/api.env. A new value makes every stored DVR password unreadable. Also store a copy offline (a password manager, or paper in a safe), separate from the backups.

Check

  • ls -l .env deploy/*.env shows -rw-------.
  • No placeholder text is left: grep -n '<' .env deploy/*.env prints nothing.
6

Point the domain at the server DNS provider

An A record from zit.example.org to SERVER_IP. DNS changes can take a while to spread, so do this early.

Check

  • dig +short zit.example.org (or nslookup) returns SERVER_IP.

Internal network only (no public DNS)

Use your organization's internal DNS and certificate authority, and change the two ssl_certificate paths in the nginx template to those files. Or, if you own a public domain, Let's Encrypt's DNS challenge (certbot with your DNS provider's plugin) issues a trusted certificate without the server being reachable from the internet. Skip step 7 in either case.

7

Get the HTTPS certificate server

Let's Encrypt, free, renewed automatically. Get it before starting the containers: nginx won't start without the certificate files.

sudo apt install -y certbot
sudo certbot certonly --standalone -d zit.example.org -m you@example.org --agree-tos --no-eff-email

# renewals: certbot needs port 80 for a few seconds, so stop nginx around it
sudo tee /etc/letsencrypt/renewal-hooks/pre/zit.sh >/dev/null <<'EOF'
#!/bin/sh
cd /srv/zit && docker compose stop web
EOF
sudo tee /etc/letsencrypt/renewal-hooks/post/zit.sh >/dev/null <<'EOF'
#!/bin/sh
cd /srv/zit && docker compose start web
EOF
sudo chmod +x /etc/letsencrypt/renewal-hooks/pre/zit.sh /etc/letsencrypt/renewal-hooks/post/zit.sh

Check

  • sudo ls /etc/letsencrypt/live/zit.example.org/ shows fullchain.pem and privkey.pem.
  • After step 9: sudo certbot renew --dry-run succeeds. The site goes down for a few seconds during it, which is expected.
8

Start the database and move the data server

Start Mongo alone, copy the current data into it, then copy the pin photos. Login sessions are not copied: everyone logs in once on the new server, which is expected because the session secret is new.

cd /srv/zit
docker compose up -d mongo
docker compose ps                      # wait until mongo is "healthy"

# 1) database: Atlas → the new Mongo. In Atlas → Network Access, temporarily allow SERVER_IP.
read -rs ATLAS_URI                     # paste the Atlas connection string (not saved in shell history)
docker run --rm mongo:8.0 mongodump --uri "$ATLAS_URI" --db Zit --excludeCollection sessions --archive --gzip > /tmp/zit.archive.gz
docker compose exec -T mongo sh -c 'mongorestore -u "$MONGO_INITDB_ROOT_USERNAME" -p "$MONGO_INITDB_ROOT_PASSWORD" --authenticationDatabase admin --archive --gzip' < /tmp/zit.archive.gz
shred -u /tmp/zit.archive.gz; unset ATLAS_URI

# 2) photos: from the machine the server runs on today (its server/uploads/pins folder)
#    on that machine:  scp -r server/uploads/pins deploy@SERVER_IP:/tmp/pins
docker compose up -d api               # creates the uploads volume
docker compose cp /tmp/pins api:/data/uploads/
docker compose exec -u root api chown -R node:node /data/uploads
rm -rf /tmp/pins

Option A staying on Atlas

  • Delete the mongo service and the mongo-data volume from docker-compose.yml, and the depends_on: mongo lines from api.
  • In Atlas → Network Access, allow only SERVER_IP, and remove 0.0.0.0/0 if it's there.
  • In Atlas → Database Access, create a user with readWrite on Zit only, and put its connection string in DB=.
  • The free Atlas tier (M0) has no backups, so step 12's script backs it up for you.
  • Only the photos need to be copied.

Check

docker compose exec mongo sh -c 'mongosh -u "$MONGO_INITDB_ROOT_USERNAME" -p "$MONGO_INITDB_ROOT_PASSWORD" --quiet --eval "
  const z = db.getSiblingDB(\"Zit\");
  printjson({users: z.users.countDocuments(), pins: z.pins.countDocuments(), units: z.units.countDocuments(), roles: z.roles.countDocuments()})"'
docker compose exec api sh -c 'ls /data/uploads/pins | wc -l'    # = number of pins that have photos

The counts should match Atlas. Then remove SERVER_IP from Atlas's network access if you're leaving Atlas.

Build and start everything server

The first build takes a few minutes: it installs packages and builds the React app.

cd /srv/zit
docker compose build
docker compose up -d
docker compose ps                     # all three "running", api and mongo "healthy"
docker compose logs -f api            # Ctrl+C to stop following

Check

  • The API log shows MongoDB connected (Zit) and Server is running on port 4586, with no warning about SESSION_SECRET or TRUST_PROXY.
  • If api keeps restarting, see Troubleshooting. The first log lines name the bad setting without printing its value.
10

Check it end to end server + phone

Proof that HTTPS, headers, the proxy, cookies and closed ports all work, before real users arrive.

curl -sI http://zit.example.org | head -3            # 301 → https
curl -s https://zit.example.org/api/health            # {"status":"ok"}
curl -sI https://zit.example.org/zit-web/ | grep -iE 'strict-transport|content-security|x-content-type'
curl -sI https://zit.example.org/zit-web/pins | head -1   # 200 (a page refresh inside the app works)

# from ANOTHER machine: only 22, 80 and 443 may be open
nmap -Pn -p 22,80,443,4586,27017 zit.example.org

Check on a phone, over mobile data (not Wi-Fi)

  • Open https://zit.example.org. It redirects to /zit-web/ with a lock icon and no certificate warning.
  • Log in, then open the pins page: the map tiles appear.
  • Open a pin and reveal its DVR password. If it shows correctly, DVR_SECRET is right.
  • Upload a photo, then open it.
  • Refresh the page: you stay logged in.
  • Log out, then press Back: you get the login page, not data.
  • On a PC (DevTools → Application → Cookies): zit.sid is HttpOnly, Secure and SameSite=Lax.
11

Clean up the data the app (admin)

Leftovers from development.

  • In ניהול → משתמשים, delete the test accounts created during development (security report M6).
  • Give the admin a long password (12+ characters). New passwords must be at least 8 characters.
  • Nothing to do for older passwords: each user's stored hash is upgraded to the stronger setting (bcrypt cost 12) automatically at their next login.

Check

  • The users list shows only real people, and at least one admin. The server won't let you remove the last admin.
12

Backups (and a test restore) server

A nightly copy of the database and the photos, kept for 14 days. Copy them off the server too: a backup on the same disk doesn't survive losing that disk.

chmod +x /srv/zit/deploy/backup.sh
sudo /srv/zit/deploy/backup.sh && ls -lh /srv/zit-backups     # run once by hand
sudo crontab -e
# add this line: every night at 02:30
30 2 * * * /srv/zit/deploy/backup.sh >> /var/log/zit-backup.log 2>&1

Test a restore once now, and then every few months. This loads the backup into a separate database, so the live data isn't touched:

cd /srv/zit
docker compose exec -T mongo sh -c 'mongorestore -u "$MONGO_INITDB_ROOT_USERNAME" -p "$MONGO_INITDB_ROOT_PASSWORD" --authenticationDatabase admin --archive --gzip --nsFrom "Zit.*" --nsTo "ZitRestoreTest.*"' < /srv/zit-backups/db-YYYY-MM-DD.archive.gz
# compare counts with step 8's check (use "ZitRestoreTest"), then remove the copy:
docker compose exec mongo sh -c 'mongosh -u "$MONGO_INITDB_ROOT_USERNAME" -p "$MONGO_INITDB_ROOT_PASSWORD" --quiet --eval "db.getSiblingDB(\"ZitRestoreTest\").dropDatabase()"'
tar tzf /srv/zit-backups/uploads-YYYY-MM-DD.tgz | head      # the photos are in the archive

Off-server copy

Copy /srv/zit-backups to another machine every night (rsync over SSH, or an encrypted cloud bucket). The backups contain personal data and the encrypted DVR passwords: keep them only where the app's data may be. Keep DVR_SECRET somewhere else; together with a backup, it can read every DVR password.

13

Retire GitHub Pages and keep it running GitHub + server

The old public copy of the app goes away; then the routine for updates.

  • GitHub Pages: repo → Settings → Pages → unpublish, then delete the gh-pages branch. That old build is still public there. Afterwards the predeploy/deploy scripts and public/404.html can go; Claude can make that small code change.
  • Deploying a new version: 
    cd /srv/zit
git fetch --tags && git checkout v1.1.0
docker compose build && docker compose up -d
docker compose ps
    Run the tests on your PC before tagging. Users may need to refresh once; index.html is never cached, so they get the new version.
  • Rolling back: git checkout v1.0.0 && docker compose build && docker compose up -d. The data is untouched: the app has no database migrations.
  • Monthly: run npm audit on your PC (server/ and react/), and update the base images with docker compose build --pull. Check disk space (df -h, docker system df) and the backup log, and delete old images with docker image prune.
  • Monitoring: a cron job or an uptime service polling https://zit.example.org/api/health (it only says whether the DB is up). Certificates renew automatically; sudo certbot certificates shows the expiry date.

deploy/nginx.conf.template 
# ${DOMAIN} is filled in from the environment when the container starts (nginx's own $variables are left alone)

# http → https
server {
    listen 80;
    server_name ${DOMAIN};
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    http2 on;
    server_name ${DOMAIN};
    server_tokens off;

    ssl_certificate     /etc/letsencrypt/live/${DOMAIN}/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/${DOMAIN}/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_session_cache shared:SSL:10m;

    client_max_body_size 1m;

    location = / { return 302 /zit-web/; }

    # the React app. NOTE: add_header inside a location replaces the server-level ones, so all are listed here
    location /zit-web/ {
        root /usr/share/nginx/html;
        try_files $uri $uri/ /zit-web/index.html;

        add_header Cache-Control "no-cache" always;
        add_header Strict-Transport-Security "max-age=31536000" always;
        add_header X-Content-Type-Options "nosniff" always;
        # OSM's tile servers require a referrer, so not "no-referrer"
        add_header Referrer-Policy "strict-origin-when-cross-origin" always;
        add_header Permissions-Policy "camera=(), microphone=(), geolocation=(self)" always;
        add_header Content-Security-Policy "default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: https://*.tile.openstreetmap.org; font-src 'self'; connect-src 'self'; manifest-src 'self'; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'" always;
    }

    # the API: "/api/x" → "http://api:4586/x" (the trailing slash strips /api). helmet adds the API's headers
    location /api/ {
        proxy_pass http://api:4586/;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        # exactly one hop (nginx), matching TRUST_PROXY=1; the client can't fake this value
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;

        # photo uploads: up to 10 × 25MB per request, phones can be slow
        client_max_body_size 260m;
        client_body_timeout 300s;
        proxy_send_timeout 300s;
        proxy_read_timeout 300s;
    }
}

#!/bin/sh
# Nightly backup of the database and the pin photos, kept 14 days.
# Run as root from cron (step 12). Copy /srv/zit-backups off the server as well.
set -eu
cd /srv/zit
DIR=/srv/zit-backups
DAY=$(date +%F)
umask 077
mkdir -p "$DIR"

# database, without login sessions. Option B (container):
docker compose exec -T mongo sh -c 'mongodump -u "$MONGO_INITDB_ROOT_USERNAME" -p "$MONGO_INITDB_ROOT_PASSWORD" --authenticationDatabase admin --db Zit --excludeCollection sessions --archive --gzip' \
  > "$DIR/db-$DAY.archive.gz"
# Option A (Atlas): put ATLAS_BACKUP_URI=... in /srv/zit/deploy/backup.env (chmod 600) and use instead:
#   . /srv/zit/deploy/backup.env
#   docker run --rm mongo:8.0 mongodump --uri "$ATLAS_BACKUP_URI" --db Zit --excludeCollection sessions --archive --gzip > "$DIR/db-$DAY.archive.gz"

# photos (the "uploads" volume of the "zit" compose project)
docker run --rm -v zit_uploads:/data:ro alpine tar czf - -C /data . > "$DIR/uploads-$DAY.tgz"

# keep two weeks
find "$DIR" -type f -mtime +14 -delete
echo "$(date -Is) backup ok: $(du -sh "$DIR" | cut -f1)"
