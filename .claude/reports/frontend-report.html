How it's built

  • One API client src/api/client.js sends the cookie, handles JSON and photo uploads, and turns server errors into Hebrew messages (for example "שם המשתמש כבר קיים במערכת" on a duplicate). Every 401 signs the user out of the app. A 503 never does.
  • Login state AuthContext asks /auth/me once. RequireAuth guards every page except / and /login. If the server can't be reached, protected pages show a retry, while the calculator keeps working.
  • Skeletons only when needed useDelayedFlag shows a skeleton only after 300ms, so a fast load doesn't flash grey. A test checks that 50ms shows nothing and 400ms shows the skeleton.
  • Icons, no text placeholders Lucide icons: no photo → an "image off" icon, empty unit → "map pin off", empty history → "history", no connection → "wifi off". Every icon-only button has a Hebrew aria-label.
  • Your colors only Red, brown, grey, slate, off-white and ink from the old colors.js, now CSS variables in index.css. Text on the grey background uses ink instead of slate, for contrast. Heebo ships with the app (no Google request), and every time uses fixed-width digits.
  • Hebrew and phones <html lang="he" dir="rtl">, bottom tab bar on phones that moves into the header on wide screens, 44px+ touch targets, native date/time pickers, phone safe areas.
  • Map loads only where needed Leaflet is about 155 KB, so it loads only on map pages.

What the tests caught (fixed)

  • Screen readers heard the error as part of the dropdown's name In the admin form, the error text sat inside the <label>, so the role field was read as "תפקיד צריך לבחור תפקיד". The error is now outside the label and linked with aria-describedby.
  • Logout could land on the login page instead of the calculator The protected-page guard reacted before the navigation to /. Logout now leaves the protected page first, then ends the session.
  • Two "add pin" buttons on an empty unit The round button is hidden when the empty state already offers one.

Run it

  1. Server: cd server, then npm run dev (port 4586).
  2. App: cd react, then npm run dev, and open http://localhost:5173/zit-web/. Vite forwards /api to the server.
  3. Tests: npm test in react/ (fake server, about 10s). npm run test:contract starts a real server on zit_test and drops that database afterwards.
